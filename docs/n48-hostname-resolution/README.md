# Configure hostname resolution

Companion notes for the video. Not affiliated with or endorsed by Red Hat.

**On-screen captures are from Rocky Linux 10.2, a RHEL-compatible rebuild. It is not Red Hat Enterprise Linux.** The prompt line is printed by the lab script in the default RHEL format; the commands and their output are real.

**Two steps are done silently before the demo:** the lab removes any old `web1` line from `/etc/hosts` (`sudo sed -i '/web1/d' /etc/hosts`) and deletes any old connection named `lab1`, so it can be re-run. This is said in the video. The demo itself changes the system: it appends a line to `/etc/hosts` and adds a connection `lab1` on a virtual `dummy2` interface with a DNS server.

## Exam objective (exact wording)
Configure hostname resolution

## What the video covers
1. A name is resolved from sources in order; `grep '^hosts' /etc/nsswitch.conf` shows the order (files, then dns, then myhostname).
2. `/etc/hosts` holds lines of address plus names; `getent hosts NAME` asks the system the way programs do.
3. `echo 'ADDRESS FULLNAME SHORTNAME' | sudo tee -a /etc/hosts` appends a line.
4. `/etc/resolv.conf` is generated by NetworkManager and lists the DNS server.
5. `nmcli connection modify CONN ipv4.dns SERVER` stores a DNS server in a connection; `nmcli -f ipv4.dns connection show CONN` shows it. After a reboot both settings remain.

## Honest limits
- The DNS server `192.168.51.53` on the dummy connection does not exist; the demo shows the saved setting, not a live DNS lookup. The contents of `/etc/resolv.conf` after activating `lab1` are not shown.
- Not covered: `hostnamectl set-hostname` (changing this machine's own name), `dig`/`nslookup`, `resolvectl`, search domains, IPv6 DNS servers, editing `/etc/nsswitch.conf`.
- The demo leaves the `web1` line and connection `lab1` in place; undo with `sudo sed -i '/web1/d' /etc/hosts` and `sudo nmcli connection delete lab1`.
- The checker reads state only.
